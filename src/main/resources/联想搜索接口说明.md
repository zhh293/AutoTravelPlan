# 联想搜索接口功能说明与实现细节

## 目标概述
- 在后端新增联想搜索接口，实时调用高德输入提示 API，按页返回结果，避免一次性将全部数据下发。
- 使用 Redis 缓存热点关键词，提供企业级缓存策略以提升响应速度与稳定性。
- 返回结构包含展示字段：上方城市名加粗，下方附属信息为小字，供前端直接渲染。

## 接口说明
- 路径：`GET /search/suggest`
- 控制器位置：`src/main/java/com/zhh/handsome/gaodemcptest/controller/SearchController.java:19`
- 依赖服务：`SearchService.suggest(...)`（`src/main/java/com/zhh/handsome/gaodemcptest/service/SearchService.java:33`）

## 请求参数
- `keyword` 必填，输入关键词，如 `安阳`
- `city` 选填，限定城市范围，如 `北京`
- `page` 选填，默认 `1`，最小 `1`
- `size` 选填，默认 `10`，最大 `50`

## 返回结构
- 字段
  - `page` 当前页码
  - `size` 每页大小
  - `total` 总条数（基于本次联想结果）
  - `fromCache` 是否来自缓存
  - `items` 联想列表，元素包含：
    - `id`、`city`、`province`、`district`、`adcode`、`address`
    - `title` 上方主标题（城市/地点名）
    - `titleBold` 固定返回 `true`，前端可按此加粗
    - `subtitle` 下方附属说明（省份/城市/区县/地址串联）
    - `subtitleSmall` 固定返回 `true`，前端渲染为小字

## 响应示例

## 外部 API
- 调用接口：`https://restapi.amap.com/v3/assistant/inputtips`
- 参数
  - `keywords` 用户输入关键词
  - `key` 高德 Web/REST Key（需自行申请）
  - `type=poi` 返回 POI 联想
  - `datatype=all` 返回更全面的提示
  - `city` 可选，限定范围
  - `citylimit=false` 不强制城市限定
- 关键实现：`src/main/java/com/zhh/handsome/gaodemcptest/service/SearchService.java:66`

## 分页设计
- 高德输入提示不提供原生分页，因此后端对返回列表进行切片分页，避免一次性返回所有数据，见 `slice(...)`（`src/main/java/com/zhh/handsome/gaodemcptest/service/SearchService.java:151`）。
- 限制 `size` 最大为 `50`，防止客户端请求过大页容量。

## Redis 缓存策略（企业级）
- 连接与序列化：
  - 配置：`src/main/java/com/zhh/handsome/gaodemcptest/config/RedisConfig.java:15`
  - 使用 `GenericJackson2JsonRedisSerializer`，确保跨服务兼容的 JSON 存储
- Key 设计
  - 列表缓存：`search:suggest:list:{keyword}:{city}`
  - 分页缓存：`search:suggest:page:{keyword}:{city}:{page}:{size}`
  - 热点统计：`search:hot:zset`（Sorted Set，按关键词计数）
- TTL 策略
  - 一般列表：`300s + 随机抖动(30~120s)`
  - 热点列表：`1800s + 随机抖动(30~120s)`，热点判定阈值 `>= 100` 次
  - 空结果：`60s`（缓存空对象，防止穿透）
  - 分页切片：热点 `~900s`，普通 `~180s`，均带抖动
- 热点统计与判定
  - 每次请求对关键词 `ZINCRBY` 计数：`src/main/java/com/zhh/handsome/gaodemcptest/service/SearchService.java:165`
  - 热点检测：`src/main/java/com/zhh/handsome/gaodemcptest/service/SearchService.java:170`
- 缓存生效点
  - 优先命中分页缓存 → 命中则直接返回
  - 未命中分页缓存 → 命中列表缓存则切片 → 回填分页缓存
  - 双未命中 → 请求高德 → 回填列表与分页缓存

## 前端展示约定
- 加粗与小字通过布尔字段传达：
  - 使用 `title` + `titleBold=true` 渲染加粗主标题
  - 使用 `subtitle` + `subtitleSmall=true` 渲染附属小字
- 结构已按“城市名在上、附属信息在下”输出，不需要后端返回 HTML，前端无框架即可按样式实现。

## 配置与密钥
- 应用配置：`src/main/resources/application.properties:1`
  - `amap.rest.key=FAKE_AMAP_REST_KEY_0000000000000000`（占位，需替换为你申请的 Key）
  - `spring.data.redis.host=localhost`
  - `spring.data.redis.port=6379`
  - `spring.data.redis.password=`（如有密码请填）
  - `spring.data.redis.database=0`
- 依赖新增（Redis）：
  - `pom.xml:34` 添加 `spring-boot-starter-data-redis`
- 实际部署注意
  - 将 `amap.rest.key` 替换为你的真实 `Web/REST Key`，并建议只在服务端使用，避免前端泄露
  - 生产环境为热点关键词设置更高 TTL，或开启预热任务
  - 可在不同城市维度区分缓存 Key，以降低数据混淆风险

## 使用示例
- 请求：
  - `GET /search/suggest?keyword=安阳&page=1&size=10`
  - 可加 `city=北京` 限定城市
- 返回：
  - `items[0].title="安阳"`，`items[0].titleBold=true`
  - `items[0].subtitle="河南省 安阳市 北关区 文峰大道"`，`items[0].subtitleSmall=true`

## 可选扩展
- 如需原生分页：可改用“高德地点文本检索”接口（`/v5/place/text`），服务层以其 `page_num/page_size` 做服务端真实分页；当前实现以“输入联想”为准，满足自动提示场景且具备响应与缓存表现。
